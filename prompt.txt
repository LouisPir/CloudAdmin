## 🎭 Narrative Arc (CRITICAL — BUILD A STORY)

Structure the presentation as a **3-act performance engineering story**:

### **Act 1 — Baseline Bottlenecks (V1 & V2)**

* Python → Spring Boot migration
* Problems:

  * Connection limits
* Result: System collapses under load

---

### **Act 2 — Distributed Bottleneck (V3)**

* Introduced Redis cache (cache-aside)
* Result:

  * DB load drops significantly
  * BUT new bottleneck appears: **network latency (~6–10ms per Redis call)**
  * Throughput capped (~2,337 req/s)

👉 Key insight: *Fixing one bottleneck revealed another*

---

### **Act 3 — The Ultimate Trade-off (V4 vs V4-bis)**

#### Improvements:

* Replaced `LIKE` with exact-match filters → index usage
* Added B-Tree indexes + FULLTEXT index
* Column projection (removed large fields from list queries)
* Increased HikariCP pool (20 → 80)

#### A/B Test:

* **V4 (Hybrid Cache)**
  Redis (aggregations) + Local cache (list endpoint)
  → ~4,576 req/s
  → scalable, distributed, slightly slower

* **V4-bis (Pure Local Cache)**
  All caches in-memory (no Redis)
  → ~4,814 req/s
  → maximum performance, NOT horizontally scalable

👉 This is the **final design trade-off**
